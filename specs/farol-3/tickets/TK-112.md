# TK-112 — `farol sync`: conhecimento que acompanha a fonte

## Objetivo e limites

Levar o `source reconcile` + worker 2.0 para a jornada. Detecção de mudança por
tipo: hash de arquivo, ETag/Last-Modified/sitemap `lastmod`, commit Git,
metadados de vídeo/arXiv versão (`v2`). Reprocessa só artefatos alterados;
invalida derivados via lineage.

Não inclui: daemon/watcher residente (o agendador do SO chama `sync`).

## Sequência TDD (S1)

- [ ] 112.1 RED: fonte inalterada → `sync --json` = `no_change`, zero escrita.
- [ ] 112.2 RED: um arquivo alterado → só seus blocos reextraídos/reindexados; outros hashes intactos.
- [ ] 112.3 RED: mudança em bloco citado por skill → tarefa de síntese só para essa skill; skill ativa preservada até aceite.
- [ ] 112.4 RED: fonte removida/revogada → hits somem, skill afetada marcada `stale`.
- [ ] 112.5 RED: `sync --schedule cron --dry-run` imprime linha exata; `--install` idempotente e `--remove`.
