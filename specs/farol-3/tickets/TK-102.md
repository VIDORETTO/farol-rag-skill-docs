# TK-102 — Jornada `farol add` / `farol build` / `farol status`

## Objetivo e limites

Uma jornada curta sobre `KnowledgeProject` existente: projeto implícito no
diretório atual (`farol.yaml`), `add` registra fontes (tipo inferido), `build`
executa extração → taxonomia → tarefas de síntese → índice → promoção, e
`status` mostra o próximo passo em linguagem simples.

Não inclui: novo estado paralelo; remover a hierarquia `lifecycle` (vira avançada).

## Contrato técnico

- `build` é retomável e idempotente; estados visíveis: `extracting`,
  `awaiting_agent` (tarefas pendentes), `facts-ready`, `ready`.
- `facts-ready`: MCP consultável, skills ainda estruturais e marcadas como tal.
- Saída humana por padrão, `--json` estável para agentes.

## Sequência TDD (seam S1)

- [ ] 102.1 RED: `farol add <pasta>` + `farol status --json` lista a fonte com rights pendente.
- [ ] 102.2 GREEN: `journey.add` delegando a `project source register`.
- [ ] 102.3 RED: `farol build` sem tarefas concluídas → `facts-ready` + tarefas emitidas; nunca `ready`.
- [ ] 102.4 GREEN: orquestração sobre operations/master.
- [ ] 102.5 RED: após submit das tarefas, `build` → `ready`, pacote válido, geração promovida.
- [ ] 102.6 RED: interrupção no meio do build → retomada sem duplicar efeitos.
- [ ] 102.7 RED (de TK-110): `--help` mostra ≤ 8 comandos de topo; hierarquia antiga sob `advanced` e aliases funcionando.

## Condição de retorno

Se exigir mudar contrato 2.0 de `master`/`operations`, parar e propor expand–contract.
