# TK-104 — Servidor MCP stdio `farol mcp`

## Objetivo e limites

Distribuir o servidor que o router já promete. Implementação JSON-RPC 2.0
mínima sobre stdio (sem dependência obrigatória; SDK `mcp` pode ser extra),
reader pinado na geração ativa, somente leitura.

Tools: `search_knowledge(query, k, filters)`, `get_document(ref)`,
`list_skills()`, `get_skill(name, chapter?)`, `next_task()` (ponte para TK-105,
somente se o pacote tiver tarefas).

Não inclui: HTTP/SSE (continua exigindo bearer; fica para depois).

## Sequência TDD (seam S2)

- [ ] 104.1 RED: subprocess `farol mcp --package <p>`; `initialize` + `tools/list` retorna as 4 tools.
- [ ] 104.2 GREEN: loop JSON-RPC, capacidades, erros tipados.
- [ ] 104.3 RED: `search_knowledge` no pacote fixture retorna hit com source/revision/locator.
- [ ] 104.4 RED: geração trocada durante a sessão → reader reabre, sem resultado misto.
- [ ] 104.5 RED: logs sem query/trecho por padrão (AC-032 2.0).
- [ ] 104.6 Atualizar router/skill operadora/harness.json com o comando real; `package_validator` verifica a tool.

## Condição de retorno

Incompatibilidade com clientes (Claude Code, Codex, Cursor) → ajustar ao spec
MCP publicado, registrar versão do protocolo suportada.
