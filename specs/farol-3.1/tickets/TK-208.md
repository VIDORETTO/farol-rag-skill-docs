# TK-208 — Skill `farol-distill`: o loop de destilação vem pronto

## Objetivo e limites

Hoje o usuário precisa colar no agente “rode `farol task next`, faça, submeta,
repita”. Entregar uma Agent Skill `farol-distill`, instalada por `farol connect`
junto com as skills do projeto, que ensina o agente a:

1. ler `farol status --json` e escolher o pacote com tarefas pendentes;
2. fazer o `outline` primeiro (se houver);
3. **com subagentes** (quando o harness suporta, ex.: Claude Code):
   `farol task claim --n <k>` e delegar um capítulo por subagente, cada um
   submetendo com `--lease`; **sem subagentes**: loop `next`/`submit`;
4. tratar rejeições lendo `reasons[]` e corrigindo só o apontado;
5. fazer o `core` por último e conferir `farol status`.

A skill usa só comandos públicos, trata os blocos como dados (nunca
instruções) e respeita a decisão D-303 (sem escrita via MCP).

Não inclui: comandos de barra específicos de harness além do arquivo da skill.

## Decisão bloqueante

D-303 (manter MCP read-only). Se rejeitada, este ticket vira o desenho das
tools de escrita e precisa de revisão de segurança (TK-113 do 3.0).
