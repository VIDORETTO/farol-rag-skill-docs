# TK-006 — Extrair Markdown e HTML com estrutura verificável

## Objetivo e limites

Entregar o primeiro caminho `SourceArtifact → IR` de alta fidelidade para
Markdown/HTML, incluindo hierarquia, listas, tabelas, código, links e origem.

Não inclui: browser JavaScript, autenticação ou assets multimodais profundos.

## Leitura em ordem

1. `docops/web_acquirer.py` → `normalize_html`, `WebAcquirer.acquire`.
2. `docops/normalizer.py` → `_extract_locators`.
3. `tests/test_web_acquirer.py` e `tests/test_normalizer.py` → segurança atual.
4. `specs/farol-2/data-model.md` → kinds/locators.

## Decisões já resolvidas

- HTML/Markdown estruturado é `structured-native`; parser degradado declara fallback.
- Conteúdo é untrusted e links não viram instruções.
- Liberdade local: biblioteca parser opcional, com fallback explicitamente classificado.

## Mapa de alterações

- Novo: adapter `text_web.py`, fixtures com lista/tabela/código.
- Existente: reutilizar aquisição/SSRF; não duplicar crawler.
- Fora: JS rendering e download de assets externos.

## Contrato técnico

- Entradas: bytes autorizados, MIME, canonical URL/path e budgets.
- Saídas: IR ordenada com heading path e locators line/section/origin.
- Invariantes: canonicalização/SSRF preservadas; links não-http filtrados.
- Erros: invalid encoding/HTML, empty, payload limit, unsafe redirect.
- Idempotência: mesmos bytes/config → mesmo IR hash.

## Exemplos de aceite

- **AC-005**: fixture equivalente MD/HTML → headings, lista, tabela e code blocks
  observáveis com origem; oráculo é a fixture, não snapshot do parser.
- **AC-009**: HTML opcional quebrado é erro no receipt; fonte principal quebrada bloqueia.
