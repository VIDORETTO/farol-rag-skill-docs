# TK-009 — Ingerir repositório por escopo intencional

## Objetivo e limites

Fazer docs/contratos/schemas/declarativos entrarem por padrão e código somente
por escopo explícito, preservando arquivo, linguagem, símbolo e linha.

Não inclui: indexar repositório inteiro, executar build ou resolver dependências.

## Leitura em ordem

1. `docops/repository_acquirer.py` → `_DOC_SUFFIXES`, acquisition.
2. `docops/source_resolver.py` → source identity/version.
3. `tests/test_repository_acquirer.py` → clone/path/submodule guards.
4. `docops/normalizer.py` → código atualmente tratado como texto.

## Decisões já resolvidas

- Seleção é por finalidade/globs seguros; não executar conteúdo.
- Submódulos e symlinks permanecem bloqueados por padrão.
- Liberdade local: parser de símbolos por linguagem pode usar fallback com fidelity declarada.

## Mapa de alterações

- Existente: `repository_acquirer.py`, `source_resolver.py`.
- Novo: `extractors/repository.py`, fixtures repo docs+schema+code.
- Fora: análise semântica/compilação de código.

## Contrato técnico

- Entradas: repo/ref/subdir/default policy + code include/exclude.
- Saídas: artifacts selecionados e IR com path/symbol/line.
- Invariantes: commit/ref registrado; ignored reason por arquivo; budgets globais.
- Erros: ambiguous scope, unsafe repo, submodule, size/file count exceeded.
- Efeitos: clone temporário privado e cleanup controlado.

## Exemplos de aceite

- **AC-008**: repo fixture inclui README/OpenAPI por padrão, exclui `src/*.py`; com
  include explícito, função entra com line/symbol.
- **AC-033**: excesso de arquivos aparece no plan antes da extração.
