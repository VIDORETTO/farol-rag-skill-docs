# TK-012 — Gerar router global e contrato de consulta

## Objetivo e limites

Classificar consulta conceitual/factual/híbrida, selecionar skills pela taxonomia
e construir QueryRequest governado com abstenção/conflito.

Não inclui: ranking RAGFlow de produção.

## Leitura em ordem

1. `docops/retrieval.py` → `route_query`, `_rank`, citations.
2. `docops/templates/router.md` → regra atual.
3. `docops/master.py` → `query_project_evidence`, filtros/elegibilidade.
4. `skills/fastapi-router/SKILL.md` → router piloto.

## Decisões já resolvidas

- Conceptual usa skills; factual backend; ambígua/atual/alto risco usa ambos.
- Filtro de elegibilidade antecede ranking.
- Classificação pode ser proposta pelo agente, mas plano/validação é contratual.

## Mapa de alterações

- Novo: `docops/router.py`, schemas QueryRequest/RoutePlan/EvidenceResult.
- Existente: tornar template/retrieval consumidores.
- Fora: RAGFlow adapter.

## Contrato técnico

- Entradas: query, project revision, context, as-of/region/filters.
- Saídas: route, skill IDs, backend query e outcome.
- Invariantes: projeto/revisão pinados; refs revogadas nunca retornam.
- Erros: ambiguous material route, stale reader, insufficient/conflicting evidence.
- Efeitos: consulta read-only; logs redigidos.
